# Semantic HTML과 웹 접근성

시맨틱 태그(Semantic Tags)의 개념과 사용하는 이유, 그리고 웹 컴포넌트와의 결합 시 주의해야 할 구조적 기준을 정리한 문서입니다.

---

## 1. 시맨틱 태그란?

시맨틱(Semantic)은 **"의미론적인"**이라는 뜻으로, 태그 이름만 보고도 그 안에 담긴 콘텐츠의 역할과 성격을 직관적으로 알 수 있는 HTML 요소를 말합니다.

### 주요 시맨틱 태그 목록과 역할

| 태그 | 역할 | 사용 위치 및 특징 |
| :--- | :--- | :--- |
| `<header>` | 사이트나 섹션의 도입부 | 로고, 제목, 검색 폼 등이 포함되는 최상단 영역 |
| `<nav>` | 주요 탐색 링크 모음 | 다른 페이지나 같은 페이지 내 다른 구역(앵커)으로 이동하는 메뉴 목록 |
| `<main>` | 페이지의 핵심 콘텐츠 | 문서당 단 1회만 사용 권장, 부가 정보(헤더, 푸터, 사이드바) 제외 |
| `<section>` | 주제별로 연관된 콘텐츠 구역 | 보통 내부에 제목(`<h2>`~`<h6>`)을 포함하여 하나의 독립된 주제를 이룸 |
| `<article>` | 독립적으로 떼어내도 의미가 통하는 완성형 콘텐츠 | 개별 프로젝트 카드, 블로그 포스트, 뉴스 기사 등 |
| `<aside>` | 본문과 간접적으로 연관된 부가 정보 | 사이드바, 광고, 배너 등 |
| `<footer>` | 사이트나 섹션의 하단 정보 | 저작권(Copyright), 소셜 링크, 법적 고지 등 |

---

## 2. 왜 시맨틱 태그를 써야 하는가?

1. **SEO (검색 엔진 최적화)**
   - 구글, 네이버 같은 검색 크롤러 로봇은 HTML 문서의 구조를 통해 중요한 정보를 판단합니다.
   - `<div>`로만 도배된 사이트보다 시맨틱 태그와 올바른 제목 계층(`h1` > `h2`)을 사용한 사이트가 검색 결과 상위에 노출됩니다.
2. **웹 접근성 (Accessibility - A11y)**
   - 시각 장애인이 사용하는 스크린 리더는 시맨틱 태그를 기반으로 "네비게이션 영역으로 건너뛰기", "메인 본문으로 이동" 등의 바로가기 기능을 제공합니다.
3. **코드 가독성과 유지보수성**
   - 개발자가 코드를 열었을 때 `<div><div class="header">...` 대신 `<header>` 하나만 보고도 즉각적으로 구조를 파악할 수 있습니다.

## 3. 웹 컴포넌트와 시맨틱 태그의 조화

### 이중 래퍼(Double Wrapper) 안티패턴 피하기
커스텀 엘리먼트를 사용할 때 가장 흔히 하는 실수는 시맨틱 태그로 컴포넌트를 또 감싸는 것입니다.

```html
<!-- ❌ 안티패턴: 불필요한 section 안에 또 section -->
<section id="skills" class="reveal">
  <skills-section>
    #shadow-root
      <section class="skills-container"> <!-- 중복! -->
  </skills-section>
</section>

<!-- ⭕ 올바른 구조: 커스텀 엘리먼트 자체를 구역의 루트로 활용 -->
<skills-section id="skills" class="reveal">
  #shadow-root
    <section class="skills-container">
</skills-section>
```

커스텀 엘리먼트(`<skills-section>`) 자체가 브라우저 표준 DOM 노드이므로, `id`와 `class`를 직접 부여하여 앵커 링크와 스크롤 애니메이션 기준점으로 사용하는 것이 가장 시맨틱하고 가볍습니다.
